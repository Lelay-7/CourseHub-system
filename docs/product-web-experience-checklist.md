## 3. 学生 A / B：跨账号闭环

按顺序完成，尽量复用刚创建的数据。B 不必重复 A 已体验的所有普通列表。

| 完成 | 入口与步骤 | 预期 |
| --- | --- | --- |
| ☐ | 通讯录 `/contact` → 名片 `/contact/:id`：A 搜索 B 或教师，发起好友申请；B 查看申请并接受或拒绝；再查看好友列表 | 搜索、名片、申请结果相互一致；待处理申请不会重复发送；可以解除好友 |
| ☐ | A 在设置保存隐私；B 查看 A 的名片，在好友/非好友状态核对“仅好友”，再核对“仅自己” | 详细资料和联系方式按实际权限显示；不是只在 A 自己页面隐藏 |
| ☐ | 消息 `/messages` → 私聊 `/messages/:id`：A/B 互发中文、两行文字及表情；返回会话列表 | 收发内容、时间、会话摘要一致；发送后可回看，不出现重复消息 |

| ☐ | B 下载 A 已通过审核的资料并收藏；用同一资料再次下载 | 文件正确，收藏状态按账号区分；已下载资料不重复扣分；A/B 的记录不互相串入 |

## 4. 学生与管理员：把需要处理的流程走到底

初始资料可帮助快速定位：A 的 `1000` 是驳回资料，`1001` 是待审第 2 版；B 的 `1002` 是已通过的收费资料。若联调或前面体验已改变这些状态，就使用当前列表中同状态的资料，或新建一份测试资料。

| 完成 | 连续步骤 | 预期 |
| --- | --- | --- |
| ☐ | **资料闭环**：A 在 `/material` 上传文件 → 管理员 `/admin/materials` 打开详情，下载当前文件检查，填原因驳回 → A“我的上传”打开驳回原因，修改信息并换文件重提 → 管理员检查新版本后通过 → A/B 从公开列表和详情回看 | 待审资料不向其他普通账号开放；重提版本递增，旧版本与审核原因保留；审核针对当前版本；首次通过奖励只发一次；发布后下载的是新文件 |
| ☐ | **举报闭环**：B 在一份已发布的测试资料详情举报 → 管理员 `/admin/reports` 进入关联资料核查，填写原因并选择成立下架或不成立 → B `/profile/feedback` 的“我的举报”回看 | 举报人能看到状态、结论与时间；成立下架后公开入口不再正常下载；不成立保留资料；提交的原因没有丢失 |
| ☐ | **反馈闭环**：A `/profile/feedback` 提交问题 → 管理员同一路由打开“查看与回复”并回复 → A 回看 | 管理员可从后台概览/导航到达反馈页；完整问题可读；回复结果可回看，失败时不丢回复草稿 |
| ☐ | **订单闭环**：A 兑换并保留一笔待处理订单 → 管理员 `/admin/orders` 打开“详情与处理”，填写用户可见的交付说明并确认完成 → A 订单详情回看 | 商品、用户、积分、状态准确；说明持久保存；完成后不能再取消退款。本地商品只演示领取/发放安排 |

## 6. 收尾检查与反馈

以下跨页行为各选一个典型页面确认即可，不需要对每一页机械重复：

- ☐ 搜索无结果与网络加载失败有不同提示；失败后“重试”能继续。可由我协助复现异常，不要求你操作开发者工具或停服务。
- ☐ 从带搜索条件的链接进入列表，再经顶部导航进入同一列表，打开详情后返回；搜索和页码没有串到另一个入口。
- ☐ 按钮连续点击时不会重复提交；提交中状态清楚；失败后可保留修改继续操作。
- ☐ 切换账号后，聊天、收藏、订单、隐私草稿和列表内容不显示前一个账号的私人数据。
- ☐ 未登录访问业务页会到登录入口；登录后回到允许访问的页面；退出后受保护页面不能继续操作。`/` 和无效地址会进入登录/会话引导，不应出现白屏。
- ☐ 用自己常用的桌面窗口宽度浏览三主题，确认设置、登录、个人中心和主要业务页的信息顺序、字号、留白、按钮及弹窗是否合意。无需再做长时间手机测试。
