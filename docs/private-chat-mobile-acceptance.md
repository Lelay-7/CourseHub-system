## Android：Windows 电脑通过 USB 接入

电脑前端启动命令（PowerShell）：

```powershell
Set-Location -LiteralPath 'C:\Users\二货道士\Desktop\项目开发\github-project-inventory\CourseHub-system\frontend'
npm.cmd run dev -- --host 127.0.0.1 --port 3000 --strictPort
```

1. Android 开启开发者选项与 USB 调试，用数据线连接电脑并在手机确认本次调试授权。
2. 电脑 Chrome 打开 `chrome://inspect/#devices`，启用 Discover USB devices，确认能看到手机。
3. 在 Port forwarding 中将手机端口 `3000` 映射到电脑 `localhost:3000`，启用转发。只转发前端入口，API 通过现有同源代理访问后端。
4. 手机 Chrome 打开 `http://localhost:3000`，登录 A。电脑可以通过 Inspect 查看该手机页面的报错和请求。
5. 在该手机页面的调试控制台核对 `window.isSecureContext === true`，以及 `typeof crypto.randomUUID === 'function'`。验收结束关闭端口转发，停止本次测试服务。

这条接入路线不依赖手机与电脑处于同一 Wi-Fi。步骤来自 [Chrome 官方 USB 端口转发文档](https://developer.chrome.com/docs/devtools/remote-debugging/local-server)。

## iPhone：同一 Wi-Fi 的本地 HTTPS 入口

手机和电脑连同一可信局域网，准备具有手机信任证书的本地 HTTPS 入口，将页面和 `/api` 一起代理到电脑的前端 `http://127.0.0.1:3000`。证书的主机名/IP 必须与手机访问地址一致；iPhone Safari 打开这个 HTTPS 地址，电脑仍通过前端代理连接本地测试后端。此仓库默认的 Vite 服务是 HTTP，当前没有生成证书、安装信任证书、修改防火墙或启动 HTTPS 入口；这些属于实际接入时的准备操作。

不能将 `http://电脑局域网IP:3000` 直接作为发送功能的完整验收入口：私聊的客户端消息编号使用 `crypto.randomUUID()`，该 API 要求安全上下文；HTTPS 或转发后的 `localhost` 可以满足这一前提，普通局域网 HTTP 不满足。依据：[MDN randomUUID](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/randomUUID)、[MDN 安全上下文](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts)。只跳过证书警告不能视为已满足验收条件。

| 检查 | 操作 | 通过条件 |

| 正常收发 | A/B 双向互发，手机停在底部和旧消息位置分别接收 | 底部可看到新消息；浏览旧历史不会被强制拉到底部，出现新消息提示，点击后定位最新 |
| 历史分页 | 预置至少 35 条消息，向前加载，再由 B 同时发送 | 当前可见消息位置稳定，无重复气泡、消息缺失或持续忙状态 |
| 未读角标 | 手机回列表，由 B 发消息；打开会话到底部读取，再返回列表 | 角标增加；读成功后当前会话角标及时更新，全局总数随后与服务端一致 |
| 失败和只读 | 在远程调试中仅阻断一次发送请求以保留 FAILED 气泡，恢复请求；由 B 解除好友，手机刷新 | 普通失败可原 UUID 重试；解除好友后输入禁用，失败消息保留并显示无法重试，不再提供重试按钮；重新建立好友后恢复重试且不增加重复消息 |
| 前后台与网络恢复 | 放到后台/锁屏后返回；临时断网再恢复 | 无叠加轮询、错误提示轰炸；恢复后可刷新和补拉，临时网络错误不清空本账号草稿 |
| 身份清理 | 手机保留消息/草稿；另一个登录会话修改 A 密码，手机再读取/发送 | 旧凭据被拒绝后回登录，旧消息、草稿、未读清空；重新登录可正常使用 |

如不能精确阻断单个发送请求，将失败重试场景记为未测；此前自动浏览器已经覆盖该场景，不能将不确定是否提交的断网操作当成真机成功证据。密码找回邮件不属于这份键盘/布局验收，不需要真实 SMTP。

## 记录与通过标准

每台设备记录：验收日期、Git 提交、型号、系统版本、浏览器版本、输入法、接入方式、各项通过/失败/未测，以及键盘打开、只读失败气泡、历史加载的截图或短录屏。失败记录应包含操作步骤与预期/实际表现；日志不包含密码或 token。

输入区被挡、中文选词误发、身份切换残留数据、消息丢失/重复、无法发送或页面报错都应先修复再复测。只有两类真机关键项都通过，才能记录“手机真机验收通过”；未测项继续明确保留。
