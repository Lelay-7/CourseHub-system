## 证据与修复

2026-10-11 的临时验收记录保存在被 Git 忽略的 `backend/target/coursehub-*-mysql-*`；浏览器截图和 JSON summary 在 `frontend/output/playwright/private-chat-*`。每次实例核对本次绝对数据路径、MySQL 8、端口、PID 文件、进程句柄与启动时间，fixture 再核对 nonce。成功和脚本失败路径均执行专属实例清理，测试证据保留。

首发时间曾保留纳秒而重试读取 `DATETIME(3)`，固定时钟测试先失败，随后将写入/响应统一到 UTC 毫秒；H2 和真 MySQL 回归覆盖相同消息完整 DTO。管理员手机提示条曾增加顶部占用，浏览器视口测试先失败，随后用导航栏实际底边计算剩余高度。

一次独立审查由 fresh-context `gpt-6-astra` 执行，范围 `df49984..3dd4676`。下列重要问题在一次修复批次中均先复现失败，再修复和复验：

1. 重复初始化残留旧聊天及回收用户 ID：破坏性初始化按依赖先删除聊天和账号恢复表；单独增量迁移仍保留数据。真实 MySQL 两种重跑场景先失败（残留会话、恢复表外键阻断），随后通过。
2. 发送回执越过未拉取消息：已读上报以实际补拉游标为上限；测试 `[1,4]` 不再清除尚未加载的 2/3，补拉后才推进到 4。
3. 视图异步操作跨会话续跑：选择、发送、历史完成、手动刷新均校验当前会话、视图代数与认证身份；四个迟到续跑测试先失败再通过。
4. 旧失败气泡抢滚动：只跟随新发起的本地消息，已有 FAILED 气泡不能触发到底部；实际浏览器先复现 `scrollTop=3661` 而非 100，修复后保留 100 且不多报已读。
5. 向前历史与新增消息并发：保存可见消息 DOM 及像素偏移，新增消息提示继续显示；实际浏览器先复现 345px 偏移，修复后误差小于 2px。
6. 临时续期错误清空草稿：离线、超时、503 保留凭据/身份并允许重试；确定的 HTTP/业务凭据拒绝仍清理并跳登录。路由续期临时失败取消本次导航；六种请求续期场景及导航续期测试先失败再通过。
7. 历史取消后重进遇首次加载失败：补查确认旧 `loadingPrevious` 会使恢复网络后的翻页成为无操作，失败测试的请求数为 1 而非 2。重新选择时重置该标记，取消完成时清理原分页对象；旧响应仍由现有请求代数守卫隔离。

2026-10-11 的后续收尾已修复原先保留的两项轻微问题：

8. 已读完成与列表/详情刷新交错：成功响应重新查找当前会话对象，及时更新局部角标和读游标，并避免覆盖更新的已读游标。两个交错回归先复现 `0` 而非 `3`，修复后通过；另覆盖当前对象已有较新游标的场景。
9. 只读失败气泡仍提供重试：页面把当前 `can_send` 传到气泡，无法发送时保留失败文本并说明当前无法重试。正式浏览器先复现重试按钮数为 1，修复后为 0；重新成为好友后恢复重试入口，重试沿用原 UUID 且保留单个气泡。

本次整合前重新运行完整后端 175 项、前端认证/找回/私聊状态与视图 45 项、三项浏览器竞态回归、三主题 12 组合、两套契约、联系人回归和生产构建，全部通过。后端与 SQL 在这次 UI 修复中没有改变，因此没有重复创建真实 MySQL 和账号恢复验收实例；其前次证据保留在上文。没有第二轮独立审查，新增修复依据失败回归和完整检查。

## 执行取舍

- 原生工作区工具指向外层仓库，不能识别嵌套项目的提交；使用项目根内的 Git worktree。代价是应用不管理此 checkout，需按明确路径和分支操作。
- Windows 环境以 PowerShell/已验证 Python 代替 Bash 记账工具，保留相同任务简报、日志和完成合同。代价是账本需按 Git/日志核对。
- 审查初期因当前 UI 不向 `loadPrevious` 传入外部取消信号，初判保留其未暴露边界；当时判断的代价是未来调用方需处理可能保留的 `loadingPrevious` 标记。该保留判断已由下述补查推翻。
- 初次交付仅有 Chromium 视口模拟，不能据此声称真机通过；2026-10-12 已补一台 Android/vivo 浏览器的聚焦实测，其他设备与省略场景仍是下述局限。
- 补查后推翻上面的取消边界保留判断：内部切换取消加上重进首次失败也影响当前 UI，故补回归并清理忙标记。代价是增加一项回归和分页状态重置；旧请求隔离继续负责阻止迟到内容写入。
