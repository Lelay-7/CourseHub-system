# CourseHub 账号安全与密码找回设计

状态：已按用户指定方案实现，自动验证、独立 MySQL 验收及本地 SMTP 的真实浏览器完整链路验收完成；未配置真实 SMTP、未执行现有库迁移或部署。外部邮箱真实投递验收待后续配置。验证记录见 `docs/account-recovery-verification.md`。

## 目标与已有决定

用户希望项目能实际使用，并在推进中理解重要选择。登录账号独立且唯一，昵称可修改，改昵称不影响登录；找回密码选实现成本合理、真实可用的方式。保留已认可的页面布局及雾蓝、酒红、曜石黑三种配色。

本批新增“账号安全”页、已登录修改密码、已验证找回邮箱与忘记密码。不把私聊并入本批：好友关系与消息存储有独立的数据模型，账号流程验证完成后再推进。

## 方案选择

推荐 SMTP 邮件验证码：沿用现有 Spring Boot 服务与 MySQL，接入常规邮箱 SMTP 即可实际发送，不需要先接第三方账号系统。短信需要另行配置发送商，当前代码并没有真实发送服务；人工管理员重置只能作为以后补充，不适合成为普通用户的主要找回方式。

个人资料邮箱用于联系；找回邮箱用于证明账号归属。两者独立保存。用户在资料页修改联系邮箱，不会改变已验证的找回邮箱。现有邮箱不能直接迁移为“已验证”，否则任何错误填写的邮箱都可能影响账号安全。

## 用户流程

### 已登录修改密码

在“我的 → 账号安全”填写原密码、新密码和确认密码。原密码必须正确，新密码继续遵循当前统一的 6–20 字符校验，确认密码在界面校验。成功后退出所有已有会话，当前页面返回登录页，使用新密码重新登录。修改密码不修改昵称、登录账号、学号或联系方式。

### 绑定或更换找回邮箱

填写原密码和新邮箱，通过新邮箱的验证码后才成为找回邮箱。页面只显示当前绑定邮箱的脱敏形式和验证状态。更换邮箱必须再次验证原密码和新邮箱；仅填写或发送验证码不会覆盖原绑定。验证码过期、错误、被使用或尝试过多时，显示明确反馈并允许重新发送。尚未绑定的账号提示先完成绑定，联系邮箱可以作为输入建议，不自动验证。

### 忘记密码

登录页增加“忘记密码”。填写登录账号及已绑定找回邮箱，申请验证码，再填写验证码、新密码和确认密码。账号与邮箱不匹配、账号不存在或已禁用时统一显示“如果账号与邮箱匹配，验证码将发送至该邮箱”，不透露账号是否存在。验证完成只修改密码，不自动登录。没有已验证找回邮箱的旧账号仍可正常密码登录，并在登录后绑定；不能通过未验证的资料字段自动恢复账号。

## 服务与数据

新增账号安全服务，负责邮箱绑定和密码变更；验证码服务处理目的、有效期、频率和消费；邮件发送器封装 Spring `JavaMailSender`，不让控制器直接发送邮件。采用明确 DTO 和 snake_case 契约。

| 接口（拟定） | 权限 | 功能 |
| --- | --- | --- |
| `GET /api/user/security` | 已登录 | 返回脱敏找回邮箱及是否已验证 |
| `POST /api/user/security/email/code` | 已登录，原密码校验 | 向待绑定的新邮箱发送验证码，返回不含验证码的请求标识 |
| `PUT /api/user/security/email` | 已登录，原密码校验 | 校验请求标识、邮箱及验证码，保存验证绑定 |
| `PUT /api/user/security/password` | 已登录，原密码校验 | 修改密码并使旧会话失效 |
| `POST /api/auth/password-reset/code` | 公开，频率限制 | 按登录账号及找回邮箱申请验证码；统一反馈和响应结构 |
| `POST /api/auth/password-reset` | 公开，验证码校验 | 一次性消费验证码，修改密码并使旧会话失效 |

`user` 增加 `recovery_email`、`recovery_email_verified_at`、`credential_version`。找回邮箱规范化后保持唯一，现有用户验证状态为空，凭据版本默认 0。JWT 的访问及刷新令牌包含凭据版本；过滤链与刷新服务核对数据库中的当前版本。改密事务原子增加版本，使旧访问令牌和旧刷新令牌都失效。上线首次启用版本检查时要求旧令牌重新登录，不把无版本的旧令牌长期视为有效。

验证码记录包含随机请求标识、用户、目的（绑定/重置）、规范化邮箱、凭据版本、验证码校验值、失效时间、发送状态、尝试次数和消费时间。使用安全随机数产生六位验证码，校验值通过专用服务端密钥生成 HMAC，不保存明文、不记录明文日志、不返回给浏览器。校验同时匹配请求标识、用户、目的、邮箱和凭据版本。

有效期 10 分钟、同一账号/目的发送间隔 60 秒、单请求最多错误 5 次；再限制账号每小时 5 次发送和 IP 每小时 20 次申请。错误次数、发送限额和一次性消费在数据库中原子更新，多实例保持同样规则。重新发送使上一验证码失效。验证码消费和绑定/改密必须同一事务，两个并发提交只能成功一个。密码变更后同账号的旧验证码失效。绑邮箱请求对账号和待绑定邮箱同时限流；找回接口使用输入账号做限流，即使账号不存在也不能绕过。

发送先预留频率及待发送记录，SMTP 调用在数据库事务之外执行，成功后按请求标识启用该验证码；失败则标记失效，不产生可消费验证码。找回接口采用有界异步发送队列统一快速反馈，队列任务使用真实 SMTP，失败只记录脱敏诊断；文案表达“如果匹配将发送”，不宣称邮件已经到达。绑定接口可以在发送失败时直接反馈重试。重复点击和迟到的发送结果不能激活已经被替换的记录。

## 真实发送与配置

邮件服务通过部署环境配置 SMTP 地址、端口、发件账号、授权码及 TLS。不开启真实 SMTP 时接口明确提示服务未配置，生产流程不使用固定验证码。请求队列只是提交发送任务；SMTP 接收也不等于用户收件箱已收到。交付验收必须用真实邮箱完成接收、绑定、找回和新密码登录。

授权码放在本机或服务器的私密配置中，不提交到 Git，也不要求用户在聊天中发送。编码完成前不需要提供这些凭据；真实投递验收时再配置。

新增独立的增量 SQL 迁移与部署说明，不重跑初始化脚本，不直接改线上数据库。迁移先在测试库验证并备份；回滚应用时保留新增字段，避免丢失绑定信息。

## 界面和验收

“账号安全”使用现有页面容器、输入、反馈和主题变量；不在用户流程展示 JWT、SMTP、数据库字段等实现细节。提交期间禁用重复操作，验证码倒计时不代替服务端限制；失败保留可继续操作的表单。手机端逐行排列，三种主题均检查。

验收包括：原密码错误不修改；修改昵称仍可用原账号登录；未验证联系邮箱不能找回；绑定前后邮箱行为正确；验证码错误、过期、重复、并发及目的混用均被拒绝；发送限额不可绕过；旧访问/刷新令牌在改密后失效；账号 A 的迟到请求不能影响账号 B；邮件未配置或发送失败不伪装为成功。后端聚焦测试、前端行为检查和生产构建通过后，使用真实 SMTP 与两个浏览器会话完成端到端验收。
